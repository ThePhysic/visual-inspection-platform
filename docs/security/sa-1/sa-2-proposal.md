# Proposed Matroid SA-2 work

No SA-2 change is authorized by SA-1. The owner should select concrete items, affected components and desired behavior from this proposal before implementation. There is no demonstrated critical application exploit demanding an emergency patch; unresolved image advisories still warrant prompt review rather than blanket acceptance.

Orders 1 and 2 address the most relevant observed risk/uncertainty. The remaining items are local-demo/product decisions, not fabricated vulnerabilities. Public TLS, authentication, tenancy, cloud services, immutable review audit history and a remote ML service are not part of this recommended increment.

## Required regression boundaries

Preserve durable MongoDB acceptance before 202, Redis-independent admission, semantic idempotency/conflict behavior, one winning result through status/generation/token/lease guards, the persistent three-attempt budget, failed-predecessor retry lineage, review revision plus write sequence, bounded receipts and immutable model predictions. Preserve canonical auto-oriented geometry, metadata stripping, inclusive input limits, atomic publication and retained bytes after uncertain inserts. No fix may solve an orphan/resource concern by deleting potentially referenced images.

For each authorized item, first retain a small before/after reproducer and agree its desired result. Add focused regression cases rather than copying implementation details. Run lint/typecheck/unit/build and affected real integration/browser/container checks on owned data. The existing two eight-request tests need explicit budget expansion if they are to run in this security-assessment context; ordinary repository CI remains unchanged.

## Remaining assessment decisions

Before selecting a broad image refresh, close MongoDB scan coverage and triage the unresolved image-package candidates against the exact operating-system build and enabled feature. A change can be justified as routine dependency maintenance even when remote exploitability is unproven; report that rationale accurately. No assertion that all 218 advisory IDs are exploitable is supported.

If browser-origin enforcement is selected, decide how the native API, same-origin nginx, native Vite, absent/null Origin, loopback aliases, configurable ports, readiness and Host headers should behave. Test real current browser policies without granting privileges merely to force an exploit. Any public/multi-user deployment changes the threat model and requires a separate design.

Full filtered-history secret review, hosted workflow/token settings, other browsers and complete DNS-rebinding evaluation remain separate assessment gaps. A safe AI Security Platform pilot can be reconsidered only after proving approved data-only ingestion, isolation, disabled hosted transmission and private report handling; neither repository should be modified to enable it in this project increment.

SA-3 final validation and portfolio publication remain future authorized work. SA-1 evidence can support an honest account of threat modeling, scanner triage, secret protection, browser boundaries and concurrency integrity for the primary security portfolio objective. It does not support an inflated vulnerability count, an exploit claim for a blocked browser path, or a production-security certification.
