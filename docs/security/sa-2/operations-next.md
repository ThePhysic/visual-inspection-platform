# Safe restart, rollback and next milestone

SA-2 is stopped after implementation/regression. The retained application was not restarted or deployed. The following procedures are for an owner-reviewed future run; they were not executed against `vip-demo`.

## Restart and rollback safeguards

Review [file inventory](evidence/file-inventory.json), desired Host names/port and environment validation first. Native defaults remain `127.0.0.1:3001`, with loopback Host aliases; frontend requests use relative `/api` via Vite. A native caller need not send Origin. A browser must use the same frontend host/port for mutations. Full Compose explicitly permits its private service names and preserves the forwarded external port. Do not enable proxy trust or add a wildcard to bypass a mismatch.

For an authorized retained-stack restart, use its existing project name and ordinary Compose build/up or restart procedures from [containers documentation](../../containers.md); preserve all named volumes. No `down --volumes`, resource prune, database reset, image cleanup or schema migration is part of adoption. Verify health/readiness, a synthetic upload/inspection/review and existing-record image rendering on an owned test candidate first. `API_UPLOAD_CONCURRENCY` may be reduced to 1 through a deliberate native/Compose environment setting. There is no aggregate quota to configure or migrate.

Rollback is selective: preserve unrelated work and SA-1 history; revert only the reviewed SA-2 application/configuration/privacy/CI/packaging hunks and remove only its new source/test files if reverting that feature. Keep assessment evidence. Do not use a broad checkout/reset/clean or edit private instructions. Restore nginx and API admission changes together so forwarding/Host assumptions remain consistent; restoring only one can break browser admission. Rebuild the application images from the selected known source, then test in fresh disposable resources before an authorized retained-stack restart.

MongoDB **8.0.34**, Redis **8.2.8**, application dependencies, canonical formats/keys, database collections/indexes and review/worker contracts are unchanged, so this increment has no planned data migration or database downgrade. Do not infer that an arbitrary future DB image downgrade would be safe. The old cache/log defaults can be restored only by explicitly reverting their small changes; doing so does not purge existing logs/cached copies. Runtime npm can be restored by reverting only its removal line and rebuilding, although no tested startup path requires it. Action rollback should use the previously recorded version/commit after review, not an unverified moving reference.

Main audit cleanup has already removed the verified named stack. Built audit image tags/cache and private logs remain local. One **unmounted anonymous volume** lacks an ownership label; leave it alone until ownership is independently established. Do not substitute another project name into the cleanup scripts. A subsequent authorized audit must generate fresh names and explicitly own MongoDB's additional `/data/configdb` volume; historical `.tools/sa2/current.json` is evidence of a removed stack, not a live target.
